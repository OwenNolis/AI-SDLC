# Architecture Decisions — Hard Rules

These rules are non-negotiable. Every generated TA MUST follow them exactly.

## Tech Stack — MUST use exactly this, never substitute

- **Backend**: Java 21 + Spring Boot 3 + Maven. NEVER Node.js, Express, NestJS, or any other backend.
- **Frontend**: React 18 + TypeScript + Vite. NEVER Next.js, Angular, or Vue.
- **Database**: PostgreSQL 16. NEVER MySQL, MongoDB, or SQLite.
- **Logging (backend)**: SLF4J + Logback, structured JSON in production. NEVER Winston, Pino, or any Node.js logger.
- **Messaging**: NOT in use. NEVER suggest Kafka, RabbitMQ, or any message queue unless the FA explicitly requires it.
- **Container**: Docker + Docker Compose.

## ID Fields — MUST always be UUID

- ALL entity `id` fields MUST be `UUID` type. NEVER `Long`, `Integer`, or `int`.
- Example: `id: UUID` — not `id: Long`.

## API Design — MUST follow these rules

- All endpoints prefixed with `/api`.
- Error response format — MUST use exactly this structure:

  ```json
  {
    "status": 400,
    "error": "Validation failed",
    "correlationId": "uuid-here",
    "fields": { "fieldName": "error message" }
  }
  ```

- HTTP status codes: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found, 409 Conflict, 500 Internal Server Error.
- Empty list responses MUST return `200 OK` with `[]`. NEVER return 404 for an empty list.
- Pagination: `?page=0&size=10&sort=createdAt,desc`.

## Database Conventions — MUST follow exactly

- Table names: snake_case plural (e.g. `orders`, `order_items`).
- Primary keys: `id UUID` — NEVER Long or auto-increment integer.
- Timestamps: `created_at`, `updated_at` — UTC, NOT NULL.
- Soft deletes: `deleted_at` nullable — NEVER hard delete.
- Sequence numbers: use existing `sequences` table with `entity_type` + `year` columns.

## Backend Layering — MUST follow this structure

```text
Controller → Service → Repository
              ↓
          Domain model (pure Java, no Spring annotations)
```

- Controllers: HTTP only, delegate to service.
- Services: business logic + `@Transactional`.
- Repositories: Spring Data JPA interfaces only.
- DTOs: Java records for Request/Response.
- Mappers: MapStruct.

## Frontend Conventions — MUST follow exactly

- State management: React Query for server state, `useState` for local UI state. NEVER Redux or MobX.
- Forms: React Hook Form + Zod. NEVER Formik.
- Routing: React Router v6.
- API calls: Axios with interceptors (auth token + correlationId). NEVER fetch directly.
- Logging: `console.error` only for errors, suppressed in production. NEVER log to console in production.

## Security — MUST follow

- Auth: JWT Bearer token, stateless.
- Roles: `ROLE_USER`, `ROLE_ADMIN`.
- NEVER store sensitive data in logs (emails, card numbers, tokens).

## Correlation ID — MUST follow

- Generated by `CorrelationIdFilter` on the backend per request.
- Added to MDC context and included in ALL log entries.
- Returned in all error responses.
- NEVER generated on the frontend.
